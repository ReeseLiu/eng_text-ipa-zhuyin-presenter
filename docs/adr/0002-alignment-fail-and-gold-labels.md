# 對齊失敗不給建議、人工確認才成金標；優先序維持兩層

CMUdict 給的是音素／發音音節界線，不是字母切點；grapheme–phoneme 反推本質上沒有唯一正解（靜音字母、多字母一音、雙寫輔音等）。我們決定：MVP 的對齊器必須可失敗——固定一種對齊策略；切點須落在字元邊界、片段非空、拼接須還原原詞；信心低或不還原原詞時**不給建議**（可標「無法建議」），不得塞一個看起來像答案的結果。人工判定後寫入（或修正後寫入）`manual_syllables` 的 grapheme 片段列表，才視為金標。優先序維持 ADR 0001 的兩層：手填 `manual_syllables`（含已套用的建議）＞ 系統自動切分；不另開「套用建議」中間層。

## Status

accepted

## Considered Options

- 低信心仍給「最佳猜測」建議：降低空結果率，但易偏一格且易被誤當正解；否決。
- 做成「手填＞已套用建議＞自動」三層優先序：語意上可區分來源，但與 ADR 0001／現有欄位不符，且增加評估與前後端漂移成本；否決。
- 第二層直接用泛用英文 LM／bigram 從零預測切點當教學金標：語料不是教師認可切分，學到的是拼字統計；否決。若日後加機率，只在對齊器產生的**合法候選**內排序，監督訊號優先本專案已確認的 `manual_syllables` 與已知字表的 grapheme 片段列表。

## Consequences

- **對齊契約**：還原不成原詞、切點不在字元邊界、多發音對不到目前選用的 IPA → 一律不建議。多發音只對目前選用的 IPA 反推，或明確列出多組；不得默默選錯音節數。
- **套用契約**：未套用不得看起來像已寫入；套用前應可預覽；低信心不可一鍵；清除／改回自動切分要好按。可選標 `source=suggestion` 僅供日後提示，不改變優先序（已套用仍屬 `manual_syllables`）。
- **金標契約**：驗收與日後排序用的金標必須是「詞 → 期望 grapheme 片段列表」，不是「有／無建議」或僅音素界線。已知字表若缺此列表，不能直接量切點準確率。
- **實作邊界**：對齊核心只實作一處，前後端（`pipeline.py`／`browser_pipeline.js`／`app.js`）共用語意，並以契約測試鎖優先序與「未套用不寫入」。
- **未決（不阻擋本 ADR）**：具體對齊演算法細節（例如字級對齊啟發式的選型）；建議功能由誰實作；`source` 欄位是否第一版就加。演算法選定後若改變「可失敗」條件，另開 ADR 或修訂本篇 Consequences。
